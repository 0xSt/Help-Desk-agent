# POL-004: Software Installation and Licensing Policy

**Version:** 2.1
**Effective Date:** 2025-01-20
**Owner:** IT Service Management
**Applies To:** All employees and contractors

## 1. Purpose

This policy governs how software installation requests and license requests are evaluated and fulfilled, and defines when non-catalog software requires additional approval.

## 2. Approved Software Catalog

IT maintains an approved software catalog of pre-vetted applications (security-reviewed, licensed, and supported). Requests for catalog software may be fulfilled directly:

1. Confirm the software is on the approved catalog.
2. Confirm a license seat is available (or can be provisioned within standard budget).
3. Deploy via the standard remote software deployment tool.
4. Confirm successful installation and license activation with the requester.

## 3. Non-Catalog Software

Requests for software **not** on the approved catalog must be routed to the Software Approval Board for security and licensing review before installation. This applies regardless of the requester's role or urgency. The AI agent may acknowledge the request and explain the review process, but must not install non-catalog software or promise a specific approval outcome.

## 4. License Purchases

| Scenario | Approval Required |
|---|---|
| Renewing an existing license within the standard annual budget | No additional approval |
| Adding license seats within already-budgeted headcount growth | No additional approval |
| Purchasing additional seats or a new license exceeding the department's current annual software budget threshold | Budget owner approval |
| Purchasing a new enterprise-wide license or tool | Budget owner **and** Software Approval Board approval |

## 5. Application Errors and Crashes

1. Check for known issues or vendor patches related to the specific symptom before attempting deeper troubleshooting.
2. Apply available patches or configuration adjustments (e.g., memory allocation, cache clearing).
3. If no known fix resolves the issue, log a vendor support case and inform the requester of expected timelines.

## 6. Escalation Criteria

- Any request for non-catalog software (route to Software Approval Board rather than resolving directly).
- Any license purchase exceeding the department's budget threshold without documented budget owner approval.
- Repeated application crashes affecting business-critical work where no vendor fix is available within SLA.
